# REDPATH Practice

Приватный рабочий репозиторий для прохождения REDPATH Roadmap.

Он используется как Obsidian Vault и содержит личные конспекты, журналы занятий, Python-скрипты и учебные отчёты.

## Структура

```text
redpath-practice/
├── journal/       # Хронология занятий
├── notes/         # Конспекты своими словами
├── scripts/       # Python-инструменты
├── reports/       # Учебные отчёты
├── local/         # Логи, scans, PCAP и evidence
├── README.md
└── .gitignore
```

Папка `local/` не должна попадать в Git.

## Начало работы

1. Клонируй репозиторий на учебную Linux-машину.
2. Открой его в Obsidian через **Open folder as vault**.
3. Создай журнал текущей недели.
4. Открой соответствующий урок из `redpath-roadmap`.
5. Выполняй задания небольшими последовательными блоками.

Пример файлов первой недели:

```text
journal/week-01.md
notes/linux-filesystem.md
notes/linux-permissions.md
scripts/auth_summary.py
reports/week-01-summary.md
```

## Рабочий процесс

На каждом занятии:

1. Запиши цель.
2. Выполни один раздел урока.
3. Зафиксируй команды и результаты.
4. Объясни изученное своими словами.
5. Запиши ошибки и нерешённые вопросы.
6. Сделай один понятный Git-коммит.

Пример записи:

```markdown
## 2026-09-27

### Цель

Разобраться с правами файлов Linux.

### Сделано

- изучил владельца и группу;
- проверил chmod;
- сравнил права 600, 640 и 755.

### Ошибки

Перепутал права группы и остальных пользователей.

### Могу объяснить

- символьную запись rwx;
- числовую запись прав;
- назначение chmod и chown.

### Повторить

- umask;
- ACL;
- специальные права.
```

## Правила конспекта

Не копируй урок целиком. Записывай:

- собственное объяснение;
- команды, которые использовал;
- полученный результат;
- ошибки и причины;
- способы проверки;
- вопросы для повторения.

## Git-коммиты

Один коммит должен отражать один понятный результат.

Примеры:

```text
docs: add week 01 lab journal
notes: explain Linux file permissions
feat: add authentication log parser
report: add first laboratory summary
```

## Что нельзя коммитить

- пароли и токены;
- приватные ключи;
- cookies и сессии;
- содержимое `.env`;
- реальные персональные данные;
- необезличенные журналы;
- PCAP и HAR с чувствительной информацией;
- результаты проверки чужих систем;
- файлы виртуальных машин.

Такие данные должны храниться только в `local/` или вообще удаляться после завершения лаборатории.

## Завершение недели

Неделя считается закрытой, когда:

- выполнены обязательные задания;
- материал можно объяснить без урока;
- лаборатория воспроизводится;
- Python-скрипт обрабатывает ошибки;
- заполнен журнал;
- подготовлен итоговый отчёт;
- изменения сохранены в Git.

Практика проводится исключительно на собственных виртуальных машинах, учебных платформах и системах с явным разрешением владельца.
